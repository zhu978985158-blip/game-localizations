# 《魔域争霸 / Atrox》简体中文补全工具

这是针对一份已有简体中文的 Windows《魔域争霸》（Atrox）制作的**残留文字补汉化源码**。它处理剩余的英文菜单项、韩文快捷键帮助、战役标题与简介，以及对战地图名称。已有剧情和游戏数值不在本次重译范围内，图片、视频及可执行程序里的文字也没有被全面汉化。

这里公开的是本地项目编写的 Python 制作、字体补字和校验工具，以及必要的资源目录元数据。原游戏及原字体由使用者自行提供；仓库不是可直接运行的游戏，也不是某个第三方 Mod 的完整镜像。本地材料没有记录可可靠核验的原始发行下载页、作者署名或精确版本号，因此不把它冒称为官方汉化，也不提供来历不明的原包链接。原游戏、随游戏字体及其他第三方内容的权利仍属于各自权利人。

## 具体修改什么

| 目标 | 用途与范围 |
|---|---|
| `dev/atrox.pak` 中的 `gamestr.rts` | 补译 22 种英文字符串；按实际出现位置回写，保留原有编号、行序与占位符 |
| `lf_help.t2b` | 解开相邻位交换后，补译 16 段韩文快捷键帮助，保留字段字节宽度与颜色控制码 |
| 包内 26 个 `.spm` | 修改战役标题、简介的固定字段，保留其余玩法与剧情字节 |
| 外部 `maps/` 下 15 个 `.spm` | 修改对战地图显示名，保留原文件名与其他内容 |
| `font/atroxC.ffa` | 从自备原包的 `atroxA.ffa` 补入译文所需字符，校验原字符轮廓与字宽不变 |

`工具/build.py` 内的 `MAIN`、`HELP`、`DESCS`、`MAP_NAMES` 就是可编辑译表。脚本对原目录的预期是 1,016 个 PAK 文件对象、28 个目标对象改变；独立校验器预期生成 109 处文字变更记录。不同版本、不同打包布局或另一份汉化底包都不能仅凭游戏名称相同就套用。

`data/pak目录.json` 是本地分析脚本从该底包提取的文件路径、块号、大小和属性清单，含 1,016 项，用于独立回读校验；它不包含资源正文、原代码、游戏二进制或字体。

## 文件与依赖

| 文件 | 输入、输出及注意事项 |
|---|---|
| `工具/build.py` | 只读 `inputs/魔域争霸简体中文版/`，生成新的 `交付/魔域争霸_简体中文补全版/`，并生成 `校验记录/翻译对照.json`、文件清单；已有输出目录时拒绝覆盖 |
| `工具/merge_font.py` | 读取上述变更记录和自备底包字体，仅改新副本里的 `atroxC.ffa`，输出字形覆盖检查记录；执行脚本就会开始处理 |
| `工具/verify_package.py` | 对照原目录、资源清单与生成副本，检查对象差异、固定字段、控制码、地图非文字字节和所有字体；通过后生成本地完整副本 ZIP、覆盖补丁 ZIP 及报告；执行脚本就会开始处理和打包 |
| `工具/selfcheck.py` | 只使用临时内存合成数据和仓库元数据，不读游戏、字体或存档 |

需要 Python 3.9 或更新版本，以及 `fontTools`。原项目使用的字体处理接口包括 `fontTools.ttLib.scaleUpem.scale_upem`；请用包含该接口的版本。未附带 vendored 第三方库，可在自己的 Python 环境安装：

```sh
python3 -m pip install fonttools
```

字体补字使用的是底包内已有的两份字体，不是通用字体转换器。必须自行确认这些字体的使用和再分发许可；本仓库没有附带它们，也不据此授予原字体或生成字体的公开分发权。

## 自备输入与生成步骤

在本目录下准备以下结构。`inputs/`、`交付/`、`校验记录/` 都已被本目录的 `.gitignore` 排除。

```text
inputs/
  魔域争霸简体中文版.rar       # 原始归档，仅供最终报告计算 SHA-256
  魔域争霸简体中文版/          # 从同一归档自行解出的干净工作输入
    atrox.exe
    dev/atrox.pak
    font/atroxA.ffa
    font/atroxB.ffa
    font/atroxC.ffa
    maps/...
    ...                       # 同一底包的其余原始文件
```

请使用独立干净输入，不要把日常游戏目录或带正式存档的目录直接作为输入。构建器会把整个输入目录复制为新的交付副本；它不会启动游戏，也不会读写正式安装目录或存档。

从本目录运行，顺序不能颠倒：

```sh
python3 工具/selfcheck.py
python3 工具/build.py
python3 工具/merge_font.py
python3 工具/verify_package.py
```

`build.py` 保留原资源包的分配表、目录、大小和对象边界，并在复制前逐项回读；`merge_font.py` 检查新增字符和原字形；最终校验器采用独立清单回读而不是依赖写入器的目录解析结果。遇到断言失败，应先检查底包版本、输入路径和译文字节长度，不能删除断言强行生成。失败可能留下未完成的新输出，重新运行前只移走自己生成的那份输出，不要删除输入或正式游戏。

最终校验器保留了旧制作流程的本地打包步骤，会同时生成完整游戏副本归档和较小覆盖补丁；这些都被 Git 排除。完整副本包含自行提供的原游戏文件，应留在本地使用，不能当作本仓库源码成果直接公开。

## 安装、恢复与检查

先退出游戏并保留可恢复的备份。确认所有校验完成后，只把本地生成覆盖补丁里的 `dev/`、`font/`、`maps/` 放入与该底包匹配的 `atrox.exe` 所在目录，按同名文件替换。不要混用另一版本的 `atrox.pak`、地图或字体。本项目没有自动安装器。

卸载时，用自己的备份恢复被替换的 `dev/atrox.pak`、`font/atroxC.ffa` 及对应 15 个地图文件；单纯删除这些文件会让游戏缺资源。存档不是补丁的一部分，不需要删除。恢复只能撤回文件修改，不能撤销实际游玩产生的进度。

第一次检查建议使用独立游戏副本和测试存档，查看菜单颜色/等级项、快捷键帮助、三族战役标题与简介、对战地图名，以及字体缺字、截断和换行情况。

## 当前验证范围

本次源码整理已完成：三份原有脚本的语法检查、1,016 项元数据结构/唯一性检查、译文编码与字段容量检查，以及合成 PAK 的跨块读取、等长写回、非目标字节保持、循环块链/越界块/重复路径拒绝、固定字符串字段和位交换可逆性检查。整理副本只改了输入路径、第三方库导入方式，以及首次构建时创建报告目录；原制作目录未被改动。

这里没有重新读取原 RAR、游戏资源或字体，没有执行真实汉化构建、安装或打包。脚本中完整的 1,016 对象、109 字段、字体与 ZIP 校验需要使用者提供匹配原包后再运行。Windows 启动、画面布局、字体实际渲染、输入与存档兼容性均未在本次整理中验证，不能把合成数据自检视为游戏实测。
